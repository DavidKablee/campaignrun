# C35 — Parties and the campaign map
Status: done      Depends on: C08 (state packs), C10 (calendar/board), C31 (roster)
## Goal
The board was a flat grid of 38 chips that only ever showed your own Crowd. Make it read as a
results map: an actual territory, with regions coloured by who is leading, and a Party system
behind the colours so a Contender choice means something on the board.
## Done when
`pnpm verify` green; every calendar state has a region on the map; each of the six Contenders has
exactly one Party; no Party can lead more regions than another before anyone plays; the screen
shows no percentage anywhere.
## Shipped
### A Party per Contender
`packages/content/data/parties.json` — Market Union, Toolbox Guild, Ledger Society, Lantern Circle,
Speaker Collective, Chalkboard League. Each one belongs to exactly one Contender, carries a map
colour and a `platform` line that jokes about the archetype's trade. Picking a Contender now picks
your colour on the board, and the Party is shown on the roster and in the studio, not only on the
map.

`partySchema` deliberately has no `slogan`, `chant`, `symbol`, `emblem` or `logo` field, and a test
asserts none appears. Guardrail 3 bans party logos, symbols and slogans outright; the cheapest way
to keep that true is to give content nowhere to put one.

### The map is a cartogram, not a tracing
`packages/content/data/map.json` places all 37 calendar entries on a pointy-top hex grid, rows
interlocking, laid out so the six zones stay neighbours. It is an invented landmass: no region
outline is traced from anywhere, and the shape exists only to be readable.

`apps/game/src/render/mapBoard.ts` renders it in Three.js as extruded hex prisms on a sea, with
height encoding status — not yet open, too close to call, held, held by you. Drag turns the board
within a short clamp; tapping a tile focuses it. The board builds its own toon materials rather
than reusing `materials.ts`, because those are patched with the road's shared `bend` uniform and
the map would have picked up the road curve the moment a run set it.

### Who holds a region
`packages/content/src/standings.ts`, pure and shared. Your tally in a region is your real best
Crowd there. The other five are generated from the state id with FNV-1a — R0 has no server, so
there is nothing real to show, and the screen says so in print rather than implying otherwise.

**The generated deal is balanced by construction, because guardrail 5 says the six Contenders are
equal and a 37-region board has to make that true, not merely likely.** The first attempt drew six
independent values per region and left one Party leading 13 regions and another leading 1 before
anyone had played — ordinary small-sample noise, and completely unacceptable on screen. Now a
region's six values are drawn from its state id, sorted into ranks, and the ranks are dealt onto
the parties by an offset walking a scrambled cycle down the layout, so each block of six regions
deals every rank to every Party exactly once. Across the whole map no Party leads more than one
region more than any other, and party identity never touches the value itself — only which rank it
is handed.

### Not a poll
Guardrail 2 allows no polling-style percentages until 200 uniques per state, so the screen has
none. The tally bar is a count of **regions held**, the focus panel lists Crowd integers, and the
legend states that rival Crowd is generated for play and not collected from anyone. "Too close to
call" is a real outcome (top two within `contestedWithin`), which is also what keeps a region
neutral-grey rather than forcing a leader.

### Tests (40 content, was 24)
- `is one invented Party per active Contender` and the reverse — no Party points at a Contender
  that does not exist.
- `carries no slogan, emblem or symbol field (guardrail 3)`.
- `passes the name guardrail like every other content file` — parties.json goes through the same
  hashed blocklist as everything else, and asserts the blocklist is not empty.
- `places every calendar state exactly once`, `never stacks two regions on the same hex`,
  `interlocks: neighbouring rows are offset by half a hex`.
- `deals an equal number of regions to every Party before anyone plays` — the guardrail 5
  invariant. Checked it fails against the independent-draw version.
- `draws a region values from the state id alone, never from a Party`.
- Player Crowd replaces the generated tally; a closed region is never held; held + contested +
  closed accounts for the whole board.
## Open
- **No real device.** Verified at 1280×900 and 390×844 in a browser pane, including a WebGL render
  and a layout measurement pass — not on a phone. This adds a fourth screen with a WebGL context,
  which is exactly the kind of thing the owed playtest exists to catch.
- **One Party per Contender is an assumption, not a spec decision.** Spec v3 never defines a Party
  system; this reads it off the existing roster because that is the only mapping the content
  supports today. If parties are meant to group contenders, or to exist independently of them,
  this is the file to change.
- **The generated rivals are a placeholder for a server.** When C12/C14 land, regions should be
  held by real aggregate play, and `rivalCrowds` should go. Until then the honest framing is the
  one in the legend.
- **The player starts at zero everywhere**, so early boards show rivals holding most regions. That
  is intended — regions are something to take — but it has not been playtested for how it feels.
- The region chip list below the board is the accessible control (the canvas is `aria-hidden`).
  It is seven rows tall on a phone; a zone-grouped or collapsed picker would be better.
