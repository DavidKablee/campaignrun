# C63 — Mobile gameplay pass

## Why
On a phone the rider drifted off the side of the screen and the game felt unresponsive. Cause of the first: `GameRenderer` aimed the camera at `pX*0.3 + sin(z/1200·2π)·5.5` (a ±17° yaw on a straight road), followed only half the lateral offset, and kept a fixed 58–66° vertical FOV, so on a 9:19.5 phone (~29° horizontal) the rider was off-screen for roughly 40–50% of a run. Landscape never showed it.

## What
- **Camera** (`render/camera.ts`, pure `cameraFor`): portrait follows the rider fully, bounds the road-bend sway to ~1 m, widens the FOV to a ~40° horizontal target (cap 72° + speed kick) and pulls back a little. Landscape framing is unchanged (portrait weight 0, tested). Initial aspect comes from the window, not 16:9.
- **Viewport:** `ResizeObserver` and `visualViewport` resize on the canvas host; left/right safe-area insets on the HUD.
- **Gestures** (`input/gestures.ts`): flick clock starts at first movement (a slow-start swipe works); thresholds scale with the screen (0.85–1.4× of the 390 px reference); one long swipe is one lane, a reversal is the next; down must be clearly vertical to brake. `InputController.reset()` is called while the tutorial or pause card is up so queued gestures do not replay at run start.
- **Pause:** auto-pause on `visibilitychange` (hidden) and `pagehide`; Android Back / iOS edge swipe pauses via a history sentinel; Resume re-unlocks audio.
- **HUD:** pause button column 2.9 rem, HUD metric labels ≥ 0.62 rem, the radio strip button is now clickable (it was under `pointer-events: none`) and ≥ 34 px; toggling radio no longer rebuilds the run effect.
- **Resilience:** `safeStorage` (a full or blocked localStorage no longer throws out of the run-end handler), an `ErrorBoundary`, a fail-open flags fetch, and a scrollable auth screen.
- **Tests:** `test/camera.test.ts` (rider NDC < 0.8 for every lane/curve phase/aspect), extended `controls.test.ts`, `safeStorage.test.ts`, and `e2e/mobile.spec.ts` (four phone viewports at 300 m and 900 m, hidden-tab pause, Back pause, HUD target sizes). `?debug` exposes `window.__crPlayerNdc`.
- All client-side: no change to `packages/sim`, so replays are unaffected.

## Real-device check
Tested on a Samsung A16 over USB debugging; results in `docs/PLAYTEST.md`. It found one bug in the first Back-handling design (see there), fixed.

## Not done
- Only one phone tested: gesture feel (`controls.json`), the portrait FOV/pull-back and any performance work still need a device. Performance items (texture prewarm, `cloneState` pooling, a wider quality governor) are unmeasured and untouched.
- Pad-origin swipes (a swipe that starts on BEAT/PERK) are still ignored.
- Done after the first pass: the service worker is now `registerType: 'prompt'` and `main.tsx` applies a waiting update only when the screen is not `game` or `paused`; the dev server reads the repo-root `.env` (`envDir: '../..'`, serve only, so a production build never bakes in a LAN address). The `.env` API URL is a fixed LAN IP (192.168.1.221) and goes stale when the Mac changes network.
- Other findings (sign-up screen, state-pack load failure with no retry, 7.7 px labels elsewhere, 405 KB single chunk, iOS audio interruption) are in the mobile review; only the ones above were fixed.
