# C31 — Roster names back to original fiction
Status: done      Depends on: C05 (contenders), C11 (local contender store)
## Goal
The shipped roster (`Baba Bullabaa, Mr Tiko, Mr Obiliki, Comrade Yale, Mr. Don, Prof. Sarah`) read as shortened phonetic echoes of real figures, which guardrail 3 and `AGENTS.md` both forbid outright, and which spec v3 section 4.1 rule 1 rules out. Restore the original fictional roster from v3 section 4.2 and make the guardrail that should have caught this actually work.
## Done when
`pnpm verify` green; no retired name form appears in code or content except the one save-migration map; the hashed blocklist is non-empty and a test fails if it is ever emptied again.
## Shipped
- **`packages/content/data/contenders.json`** — the six are now Mama Ankara (The Market Queen), Engineer Spark (The Fixer), Captain Kobo (The Penny-Wise Skipper), Sister Beacon (The Lamp-Bearer), Uncle Boombox (The Party Starter), Madam Metronome (The Teacher). Perk ids, trade-offs and permille values are unchanged, so balance is untouched — only identity moved. Archetypes are everyday-life roles now, not political ones (v3 rule 4: the old set ran Convener/Delegate/Organiser). Barks and catchphrases rewritten to match; gender mix is 3f/3m (was 5m/1f).
- **Palettes** reworked off each character's described look rather than inherited: no green-and-white or red-and-white pairing survives, since those read as party/flag colours in a political game (v3 rule 3).
- **`packages/content/data/outfits.json`** — rekeyed, and each character now uses the props the renderer already had but nothing referenced: `fan`, `wrench`, `pouch` + `goggles`, `lantern`, `speaker`, `baton` + `bowtie`, with `headtie`/`hardhat`/`sailor`/`headphones` headwear. Four of the six previously had `prop: none`.
- **`apps/game/src/contenderStore.ts`** — the store already held a `PREVIOUS_IDS` map pointing the *other way* (v3 id → parody id), i.e. the repo had this roster once and migrated away from it. Flipped to `RENAMED_IDS` (retired id → current id), bumped persist version 1 → 2. A device that picked under the old ids keeps the same character, perk and saved outfit. The map is idempotent: an id already on the live roster is left alone.
- Id references updated in `packages/sim/src/{step,collide}.ts`, `apps/game/src/{characters,App}.tsx`, `render/materials.ts`, the sim/consent tests, the e2e spec and `docs/SPEC.md`.
- **Blocklist actually loaded.** `packages/content/data/blocklist.hashes.json` shipped with `"hashes": []` — guardrail 12 and ADR-0005 describe a hashed blocklist, but with an empty set `findViolations` could never fire, which is why the retired names passed `content:lint` every run. Seeded with 20 hashed terms (retired roster forms and earlier parody drafts) from `private/blocklist.plain.txt` (gitignored). `tools/hash-blocklist.mjs` now skips `#` comment lines so the plain file can be documented.
- Two tests in `packages/content/test/content.test.ts`: the blocklist must be non-empty, and `outfits.characters` keys must match the live roster ids exactly. 99 tests total (was 97).
## Open
- **The blocklist holds no real names.** Only retired fictional forms are hashed, because writing a real politician's list into any file is exactly what `AGENTS.md` forbids me to do. `private/blocklist.plain.txt` has a TODO marking where the legal review's list goes; re-run the hash tool after adding it. Until then the lint catches regressions toward the old roster, not a fresh real name typed into content.
- Blocklist terms are deliberately conservative: multi-word forms are used where a single token is a common word (`mr don` hashes to `mrdon`, so the Pidgin perfect marker "don" in barks is untouched). Single generic first names were left out entirely.
- `RENAMED_IDS` is the one place the retired strings still live. R0 has not launched, so no real device holds an old save — it can be deleted outright before launch to purge them, at the cost of resetting the team's own dev saves.
- `packages/sim/src/collide.ts` still keys the magnet perk off a hard-coded contender id rather than the perk id. Renamed, not fixed; logged in BACKLOG.
- **Names and looks are still placeholders pending review.** v3 section 4.1 rule 5 (show the art to 10 outsiders; redesign if more than 2 name the same real person) has not been run, and neither has the media-law review. This chunk removes a clear violation; it does not clear the legal gate.
