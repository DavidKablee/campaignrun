# C30 — Weather & time-of-day (NEPA/harmattan/Rally Saturday)
Status: done      Depends on: C23 (world/environment)
## Goal
The last chunk in the C26–C30 track: spec section 6.8's "Nigerian rhythm" — weather and time of day per state, NEPA night events, harmattan haze in the north (Dec–Jan), rainy-season flooding mood in the south, and the Rally Saturday ×2 Crowd window. Entirely client-side: a real clock read once at run start, nothing more.
## Done when
`pnpm verify` green; all weather decisions are pure functions of `(time, zone, seed)`, never a live `Date` read inside `packages/sim` or mid-run in the renderer; Rally Saturday is a real, testable Crowd multiplier, not just a visual label.
## Shipped
- **`apps/game/src/weather.ts`** (new, pure): `computeWeather(nowMs, zone, runSeed)` → `{dayPhase, isNight, isNepaOut, isHarmattan, isRainySeason, isRallySaturday}`. Called exactly once per run, in `App.tsx`, right where the run's `seed` is already generated — the one and only place a real clock gets read. Harmattan = Dec/Jan in a northern zone (NW/NE/NC); rainy season = Apr–Oct in a southern zone (SW/SE/SS); NEPA outage is only possible at night and is a deterministic roll off the run's own seed (same outage for the whole run, not re-rolled every frame); Rally Saturday = Saturday 18:00–21:00 WAT, matching the spec's exact wording.
- **Sim side** (`packages/sim/src/step.ts`, `types.ts`): a new `rallySaturdayMultiplierPermille` field on `SimState`, set once at `initState` from a caller-supplied option (default 1000 = ×1.0, so every existing call site and test is unaffected) and applied in `deliverCrowd` alongside the existing Full House/On Beat/PVC multipliers. The sim never decides *when* Rally Saturday is — it only ever applies the number it's given, keeping the "no Date/Math.random inside sim" purity rule intact. New config constant `bonuses.rallySaturdayMultiplierPermille` (2000) in `sim.json`, matching the spec's "×2 Crowd, 6–9pm WAT" exactly. New sim test proves the multiplier doubles delivered Crowd exactly, off by default.
- **Renderer side** (`apps/game/src/render/world.ts`, `materials.ts`→no change, `textures.ts`, `GameRenderer.ts`): `World` now takes an optional `WeatherContext` and applies it once in a new `applyWeather()` — a smooth day/night blend (cosine curve on `dayPhase`, not a hard cut) driving hemisphere/sun light intensity, sun colour, fog colour and draw distance, plus a sky-gradient texture swap (`skyTexture('day'|'night'|'harmattan'|'rainy')`, same baked-canvas technique as the existing day sky, just parameterised with 3 more colour ramps). Harmattan thickens the haze and pulls fog/sky toward dusty tan; rainy season pulls them toward wet grey-blue. A NEPA outage additionally darkens hemisphere/sun by a further 55% and adds a warm `PointLight` "phone torch" parented to the player (moves for free, no per-frame code).
- 6 new tests in `apps/game/test/weather.test.ts` covering day-phase smoothness, the night window, NEPA's seed-determinism and night-only constraint, harmattan/rainy-season zone+month gating, and the Rally Saturday time window including its boundaries. 97 tests total (was 90 after C29).
## Open
- No actual rain/dust particle effects — this chunk is lighting/fog/sky mood only, not a VFX pass. A reasonable next step if more atmosphere is wanted, but the spec's own wording ("weather + NEPA night-mode events") is satisfied by the mood shift.
- Weather is decided once per run from the real clock at the moment you press Start — it doesn't update mid-run (a 75–100s run never crosses a meaningful time boundary anyway, so this is a non-issue in practice, not a cut corner).
- **Live visual confirmation of the night/NEPA/harmattan/rainy variants wasn't possible in this session** — real time at verification was daytime, so only the default day-mood path was ever actually visible on screen; the alternate moods were verified through the full `pnpm verify` pass (which exercises the same Zod-validated config the renderer reads) and the dedicated `weather.ts` unit tests with fixed date fixtures, not a screenshot. A real-device playtest at night, or with the system clock set to a Saturday evening/December, would be the way to see these for real.
- Mid-session, a stale Vite HMR state (after many consecutive edits) briefly showed a Zod validation error for the new `rallySaturdayMultiplierPermille` field even though the on-disk files were already correct (confirmed by a clean `pnpm build` at the time) — a full dev-server restart cleared it immediately. Not a real bug, noted here only because it looked alarming in the console log.
