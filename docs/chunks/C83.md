# C83 — The first minute

From a review that said the first minute teaches the wrong game. The "drive first" bet stays; the rest of the product now follows it.

## What changed
- `meta.ts hasPlayed`: a Starting Story's Supporters do not make a player "returning". Splash uses it, so Grassroots Start taken before playing still gets the quick, coached trial.
- `SummaryScreen`: when no Contender is picked (the trial), the next-step buttons (Pick your Contender, Run again) sit right under the score; everything else follows. Once a Contender is picked the order is unchanged.
- Coach card: three moves (lane, hop, load). `prompt.pickupAhead` / `prompt.venueAhead` (English and Pidgin) name the gesture.
- Roster copy (`copy.rosterLock`, the lock alert): the lock is the first full campaign run. `state.ts` already skipped the lock for the trial and quick rallies; the words were wrong.
- Pause → Quit with no Contender returns to the splash.

## Tests
`apps/game/test/trialRun.test.ts` (`hasPlayed`, roster copy); `apps/game/e2e/smoke.spec.ts` (coach card teaches loading, Quit from the trial, Grassroots Start before playing). The coach card fits 844x390 and 360x640.

## Not done / unverified
- Held: the challenge link (WhatsApp, share, copy) is hidden on the trial result, because a quick rally goes on no board and a first-timer cannot yet explain the score. It returns on every result once a Contender is picked. The trial score itself cannot be sent.
- A first-timer who finishes the trial and closes the app returns to the Briefing with the default Contender shown and nothing picked. Not changed: routing them to the roster would change the "Continue campaign" path several tests use.
- The playtest has not been run, so "load at the first pickup without help" is still unmeasured.
