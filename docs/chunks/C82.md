# C82 — Mobilise: shared campaign places

From the owner: "there is this feature on Lagos Life where people meet real people and perform various actions on their phone and chat with each other… I want to build that as part of the application but focused on places and all things campaigning." The splash button becomes **Run my race**; the planning page gets **Mobilise**.

## What

### The place
- Four kinds in every state: Market, Park, Lakeside, Stadium (`packages/content/data/places.json`). Everyone in the same state and kind shares a room of up to 12; a second room opens when it is full.
- Avatars are plain citizens built with the existing character rig (`randomPerson` seeded from the account id), plus the shirt colour the server was told. The player's Contender and Studio look are never sent or shown (guardrail 10).
- Tap the ground to walk (same `stepToward` and speed on the server and the client, in `packages/content/src/places.ts`). Tap a person to mute or report them.
- Actions: Canvass (₦3, 1 Supporter), Hand out flyers (₦2), Rally the crowd (₦6, 2 Supporters, needs someone within 7 m), Wave (free). Each has a cooldown that the server enforces.
- Talk: 12 preset phrases (English and Pidgin, switchable) and 8 emoji. The server accepts only an id from the list, and the client has no text field.

### Rewards and caps
- Per Lagos day, per account, held in Postgres (`place_daily`): ₦60, 5 Supporters, 40 actions. A second tab or device cannot widen it.
- The client applies what the server says it paid (`addCoins`, `addFollowing`). Nothing reaches `packages/sim`, so replays and Contender parity are untouched and there is no store version bump.
- Each paid action adds points to `place_activity` for the state (confirmed accounts only unless `CR_REQUIRE_VERIFIED=false`); `GET /api/places/activity` returns today and the last 7 days. **The Board does not show it yet.**

### Server
- `api/src/placesHub.ts`: rooms, cooldowns, company check, ttl, in process memory (one API instance; a second instance would split a place in two). `api/src/places.ts`: routes under `/api/places` — `online`, `activity`, `join`, `rooms/:id/stream` (server-sent events, cookie-authenticated), `move`, `act`, `say`, `report`, `leave`.
- Limits in `limits.json` (`places`), validation in `validate.ts`, three new tables in `schema.sql` (`place_daily`, `place_activity`, `place_reports`).
- Nothing a player says is stored. A report is a reason from a closed list about a member in a room.

### Client
- `places/PlacesScreen.tsx`, `places/placesStore.ts` (EventSource, rejoin up to 3 times), `places/placesModel.ts` (pure), `render/placeRenderer.ts` and `render/placeScene.ts` (one merged scenery mesh per kind, name tags and bubbles as DOM).
- **Entry points:** the splash (a button under Run my race, shown to first-time players too), the planning page, and the result screen. The first version put it only on the planning page, which first-time players never see (their first run goes straight into the game), so it looked missing. Back returns to where you came from (`placesBack`).
- The button probes `/api/places/online`; if it fails the button says "Opening soon" and is disabled. A signed-out player is sent to the name screen and back (`authReturn`).
- Splash: **Run my race**, with a line under it confirming 18+ (guardrail 9 updated).
- Analytics events added to the closed list: `mobilise_open`, `place_join`, `place_action`, `place_say`.
- Draw budget: 35 draws with 2 people; each extra person is about 11 draws, so a full room is under 200 (checked in the e2e).

## Tests
`packages/content/test/places.test.ts` (9), `api/test/placesHub.test.ts` (10), `api/test/places.test.ts` (11, Postgres), `apps/game/test/places.test.ts` (5), `apps/game/e2e/places.spec.ts` (offline path; two players meeting, acting and talking). Test files now run one at a time (`vitest.config.ts`) because the API suites share a database.

## Not done
- Seen with two players only; no real phone, no crowd of 12, no load test.
- The scenery is generic per kind, not per state's landmarks.
- Board does not show place activity yet. Reports are recorded but there is no review tool.
- Presence is per instance: scaling the API past one instance needs a shared pub/sub.
- Phrase wording (especially Pidgin) has not had a native review.

## UX review (after first use)
Research notes: Lagos Life (browser life-sim, 18+, "Game Naira" with a currency exploit and data-handling questions; no verified detail of its chat), Lagos Run (danfo driving game that inspired it). The design canvas "Mobilise redesign" came out of it.

## Redesign (built)
- **Locals:** client-only wandering characters with dashed "Local" tags, `places.json` `locals {max 5, min 2}`; `localsFor(players)` thins them as real players arrive; data saver keeps the minimum. They never speak, are not counted as players and cannot be tapped.
- **First-visit coach card:** "Tap the ground to walk…" with "Got it"; remembered in `localStorage` (`cr-places-coached`), hidden while a tray is open.
- **Talk tray:** replaces the dock in the layout so the scene stays visible above it; English/Pidgin toggle lives in it, then emoji row, topic chips (Greet, Chat, Our area, Rally) and that topic's phrases.
- **Dock:** line icons, `short` labels from `places.json`, and two daily progress bars (coins, Supporters).
- **People:** tap target is measured on screen (34 px) rather than in the world; the person card has Wave at, Mute and report chips (reporting also mutes).
- **Invite:** share button in the header opens a sheet with a preview card, Share on WhatsApp (`wa.me`), Copy link and More options (Web Share, only where the browser has it). The link is `#mobilise=<state>.<kind>`; the app reads it on load, validates the state and kind, strips it from the address bar and opens that place (signed-out visitors meet the name gate, which carries the 18+ step). Tracked as `place_invite`.
- Nothing here touches `packages/sim`, the store version or replays.
- Not built: per-state scenery, a Board place-activity strip, a report review tool. Not checked: a real phone, WhatsApp's own link preview (needs a hosted page with Open Graph tags).
