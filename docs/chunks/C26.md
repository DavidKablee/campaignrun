# C26 — Ride roster complete (Keke → Grand Convoy)
Status: done      Depends on: C04 (rides/stars)
## Goal
Close the C0–C11 breadth gap on rides: 5 of 7 rides were schema-ready but locked, and their traits (size class, "ploughs light barriers", "absorbs 1 free hit", signature-ride bonus, wider magnet) were flavour text with zero code behind them anywhere in `packages/sim`.
## Done when
All 7 rides selectable once their Following gate is met; balance bot green across all ride classes (±3% Crowd parity per Contender, per ride — acceptance criteria #4 from the spec, never verified past trek before this chunk); `pnpm verify` green.
## Shipped
- `rides.json`: `keke`/`hilux`/`danfo`/`coaster`/`grand-convoy` flipped to `playable: true`; new `ploughsLight`/`freeHitPerRun`/`magnetBonusMm` fields (default false/false/0, so Trek/Okada are byte-for-byte unchanged).
- `packages/sim`: `collide.ts` grew real size-class rules — hazards tagged `sizeTag: 'narrow'|'flood'|'light'` in `sim.json`'s obstacle config become transparent to the right ride size/trait (narrow blocks M/L only, flood blocks L only, light is ploughed by Danfo+), same "continue past this entity" shape as the existing hop-clear check. Hilux's free-hit, Coaster's magnet bonus, and the Signature-Ride +10% Crowd bonus (wired from the already-inert `StateDef.signatureRide` field) all land in `step.ts`/`types.ts` as plain integer `SimState` fields set once at `initState`, keeping the sim decoupled from `@cr/content` and fully backward compatible (every existing `initState` caller — tests, showcase — needed zero changes).
- Two new tagged obstacles (`narrow-gate`, `flood-patch`) in `sim.json`; `cones`/`barricade` retagged `sizeTag: 'light'` rather than inventing new "light barrier" obstacles.
- `packages/sim/test/balance.test.ts` extended from trek-only to all 7 ride classes (6 Contenders × 120 runs × 7 rides) — confirmed ±3% parity holds with the new mechanics live.
- **Real gap found and fixed mid-chunk, outside the original plan**: only `okada` had a 3D vehicle model — every other ride would have been selectable but rendered as the character just running on foot, which would have shipped looking broken. Added `buildKeke`/`buildHilux`/`buildDanfo` (reuses the existing oncoming-traffic danfo model)/`buildCoaster`/`buildGrandConvoy` to `props.ts`, and generalized `GameRenderer.ts`'s single hardcoded `rideId === 'okada'` branch into a `RIDE_VISUALS` lookup (seat offset, lean amount, and whether the character mounts the vehicle or is hidden inside an enclosed one). Verified visually: Keke seats the character correctly; Coaster hides the character and shows the right capacity (120) with the bus filling the frame.
## Open
- Grand Convoy's spec trait "requires Spread badge" (Foothold in 24/36 states) is not enforced — that's a separate meta-progression system that doesn't exist yet. It's playable on Following alone (120,000), same gate style as every other ride.
- New vehicle models are a first pass (simple procedural geometry, same technique as the existing `buildOkada`/obstacle models) — not put through the same design iteration as the C21 character rebuild. Good enough to not ship broken; revisit if they need polish later.
