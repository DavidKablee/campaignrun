# C36 — The board becomes a world map
Status: done      Depends on: C35 (parties + map)
## Goal
C35's board was a honeycomb. Make it read as a map: a landmass with a coastline,
on open water.
## Done when
`pnpm verify` green; every region still tiles without a gap; no outline is traced from a real map.
## Shipped
`packages/content/src/mapgeo.ts` walks each region's hex slot and pushes every lattice point off
true, then the renderer extrudes the result. The land is an invented continent on a sea, with a
faint graticule behind it.

**Displacement is keyed on the point, not on the region.** A corner belongs to up to three regions
and an edge midpoint to two; each of them hashes the same snapped lattice key, so they all move it
to the same place and a shared edge stays shared. Jitter per region instead and the coastline tears
open along every border — which is what the `leaves no gap between neighbours` test exists to catch.

`apps/game/src/render/mapBoard.ts` now builds a per-region `ExtrudeGeometry` from the outline rather
than a shared hex prism, one unit tall and scaled on Y so a region can change status without
rebuilding its geometry.
## Tests (46 content, was 40)
- `leaves no gap between neighbours: a shared corner lands in one place` — the invariant the whole
  approach rests on.
- `moves every region off its hex, so the coast is not a honeycomb` — the opposite failure.
- Determinism, 12-point outlines, points within reach of their own centre, outlines centred on the
  slot the layout asked for.
## Open
- **One landmass, no bays or islands.** The coastline is ragged but the continent is a single blob;
  inlets and offshore islets would need the layout to leave deliberate gaps.
- Regions are all roughly the same size, because a cartogram's whole point is that they are. A
  size-varying map would break the shared-vertex trick and need real polygon clipping.
- The bevel means the extrusion runs -0.04..1.04, so anything placed on the top face has to clear
  it. That caught the labels once already.
