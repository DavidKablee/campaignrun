# C23 — World/environment: real CC0 integration (first pass)
Status: done (partial — see Open)      Depends on: C20, C21
## Goal
Start spending the C20 asset pipeline for real: swap some of the procedurally-built scenery for the CC0 Lagos biome kit, and give the sky a bit more atmosphere. `debug-assets.html` was a proof harness, not the integration — this is the integration.
## Done when
Visible CC0 props render correctly in-game (not just the debug harness); draw-call/triangle budgets hold; `pnpm verify` green.
## Shipped
- `world.ts`: `lagosKit()` lazily loads palm/building/parasol templates once (shared promise, not per-chunk) via `assets.ts`. Chunks built before the kit resolves fall back to the existing procedural prop for their lifetime — chunks recycle every ~40 m anyway, so the next rebuild a few seconds later picks up the CC0 model. No loading-screen/blocking needed.
- **Palm trees** (`placePalm`, used by `trees()` on `park` and `palms()` on `island`): real CC0 palm models (3 variants, random scale 0.85–1.15×) replace the primitive cylinder-stack-and-cone palm once loaded. Verified visually on both themes via a new debug harness, `/debug-assets.html?theme=park|island|market|...` (jumps straight to a theme's course distance — faster than surviving a full run to reach it).
- **Market parasols** (`stalls()`): CC0 parasol models replace the procedural cone roof on market stalls, mixed with the existing coloured umbrellas for variety.
- **Sky**: added `sunTexture()` (soft radial-gradient sun glow sprite) alongside the existing cloud sprites — the sky gradient itself (`skyTexture()`) was already a 4-stop gradient, not flat as first assumed; fixed the actual gap (no sun) rather than re-doing something that already worked.
- Verified performance via the new debug harness's frame stats: `market` theme 48 draw calls / 34.4k tris, `island` theme (the densest — CC0 palm avenue + towers) 24 draw calls / 36.5k tris. Both comfortably under the ≤150 draws / ≤120k tris budget. (The harness's own fps readout is unreliable — rAF is heavily throttled in the automated preview environment — so draws/tris, which are frame-count-independent, were used as the real signal instead.)
- Build/size impact: first-load gzip 297 KB → 325 KB (GLTFLoader is in the main bundle now, not lazy) — still ~12× under the 4 MB budget. `tools/size-check.mjs` biome-kit check unaffected.
## Open (explicitly deferred, not silently dropped)
- **Buildings**: `BUILDING_IDS` are preloaded into the kit but not placed yet. `buildings()` already has real per-building styling (shops, awnings, balconies, roofs, billboards, compound walls) that a straight CC0 model swap would flatten — this needs its own design pass (e.g. CC0 buildings as filler between procedural ones, or as the `towers()` far-background silhouette), not a rushed swap.
- **Sidewalk/curb geometry and lane-paint decals**: not added. `roadTexture()` already paints lane wear/tyre tracks into the road texture; raised 3D kerb geometry is still open.
- **LOD on far chunk slots**: not added — budgets (see above) already pass comfortably at the current 6-slot/240 m window, so this would be premature optimisation right now. Revisit if a future theme pushes past budget.
- **Low-end throttle verification**: only checked via the automated preview (which throttles rAF and can't substitute for a real mid-tier-Android frame-time measurement). Needs an actual phone/DevTools-CPU-throttle pass — tracked for C25.
