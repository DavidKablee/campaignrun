# C29 — Local ghost record/playback
Status: done      Depends on: C1 (input log), C20–C22 (renderer, character rig, movement feel)
## Goal
Build the client-side-only slice of C12: a translucent ghost of **your own personal-best run** races alongside you on your next run of a state. Friend ghosts and state top-5 ghosts need a backend (upload, discovery, moderation) and stay out of scope — this is just "my own past best," which needs nothing but `localStorage`.
## Done when
`pnpm verify` green; ghost replay is deterministic (same stored ghost → identical trajectory every time); a new run only overwrites the stored ghost when it actually beats it on Crowd; nothing about ghost recording/playback can affect live scoring (ghost position is read-only, purely visual).
## Shipped
- **Recording** (`apps/game/src/App.tsx`): the run loop already called `input.sample()` then `step()` every tick — now it also pushes an `{tick, input}` record whenever the input bitmask *changes* (not every tick — a sparse log, matching how `encodeInputLog`'s delta-varint format is meant to be used; a 75–100s run typically has a few dozen input changes, not ~5000 per-tick entries).
- **Persistence** (`apps/game/src/ghostStore.ts`, new): one ghost per `stateId` in `localStorage` (`cr-ghosts-v1`), `{stateId, seed, contenderId, rideId, ticks, crowd, log}`. `saveGhostIfBest` only overwrites on a strictly better Crowd — the comparison itself is factored into a pure `shouldReplaceGhost` function so it's unit-testable without touching `localStorage`. Only a `phase === 'finished'` run (not a breakdown) is eligible.
- **Replay** (`apps/game/src/ghostReplay.ts`, new): `computeGhostTrajectory(ghost, config)` decodes the stored log and re-runs `initState`/`step` once, up front, snapshotting `{laneX, z}` at every tick into a plain array. This is pure positional data — the ghost doesn't need to share a course seed with your live run (it's a replay of a past run on this road, not a reaction to this run's hazards), and the render loop never re-runs the ghost's sim live, just indexes into the precomputed array by the live run's own tick counter. Covered by tests for determinism and monotonic progress.
- **Rendering** (`apps/game/src/render/GameRenderer.ts`, `materials.ts`): a new `ghostMat()` — the same cached-singleton pattern as every other material in this file, a cyan-tinted translucent (opacity 0.4) toon variant — applied to a `personGeo('run')` silhouette (the same geometry already used for crowd/supporters, not the full detailed character rig — cheap, and visually reads clearly as "a ghost" rather than needing the face-texture/outline handling a full rig would need). Positioned every frame from `trajectory[tick]`, interpolated the same way the player and all other entities already are; hidden once the live run runs past the ghost's recorded length (the ghost "finishes" and disappears, rather than freezing in place).
- 7 new tests in `apps/game/test/ghost.test.ts`: base64 round-trip, the personal-best comparison in both directions, trajectory shape/determinism/monotonic-z, and that a mid-run lane-change input is actually reflected in the final `laneX`. 90 tests total (was 86 after C28).
## Open
- Only your own personal best, local-only. Friend ghosts, a state's top-5 ghosts, and server-side verified replay (the rest of spec C12) all need a backend and stay backlog items.
- No UI affordance yet announcing "racing your ghost" / showing how far ahead or behind you are — the ghost is present and positionally correct but the HUD doesn't call it out. A small polish item, not core functionality.
- **Live in-run visual confirmation hit the same preview-tool limitation as C28** (backgrounded tab, requestAnimationFrame never fires, so gameplay can't advance for a screenshot in this environment). Verified via: the full test suite (including dedicated ghost-replay tests), and a live-browser check that `ghostStore`'s save/load round-trips correctly through real `localStorage` in the actual running app (the piece most likely to have real-browser-only quirks). A real-device playtest should confirm the translucent ghost reads clearly against the road and the rest of the HUD.
