## Gotchas
- **First-timers skip roster/studio/briefing (2026-10-26).** `Splash.start()` sends `!returning && activeContenderId === null` straight to the run. `GameScreen`, `Briefing` and `SummaryScreen` already fall back to the first Contender when none is chosen; keep that fallback in step with `contenders[0]` or the trial run and the result page disagree about who ran. The e2e suite passes (`pnpm test:e2e`, 5 passed / 1 skipped by design) after installing Chromium with `PLAYWRIGHT_BROWSERS_PATH=0 pnpm exec playwright install chromium`.
- **`pnpm test:e2e` serves `apps/game/dist` via `vite preview`, not the dev server.** Run `pnpm --filter @cr/game run build` first or the suite tests whatever you last built (it failed against a stale build until rebuilt). A returning player's splash button reads "Continue campaign", not "Run my race".
- **The run loop must read `tutorialRef`, not `showTutorial`.** The loop's effect cannot depend on React state (a dep change rebuilds the whole WebGL run), so anything that should freeze the sim goes through a ref like the pause screen's store read.
- **`packages/content/src/yard.ts` owns every meta number.** `upgradeValue`, `runModifiers`, `runPayout`, `followingGain` and `upgradeReadout` all read `meta.json`, and the Yard prints what the sim is handed. Before C48 the same steps were written out again in `apps/game/src/meta.ts` and a third time in `state.ts`, which is why the shop could not state an effect. A new upgrade needs an `effect` block in `meta.json` and nothing else.
- **Following has one source: supporters delivered**, at `rewards.followingPerDelivered`, added on the result screen. It is not bought, not lost, and nothing else moves it. Any new source has to be added to the How it works tab in the same change, or the screen starts lying.
- **The rally streak counts finished rallies, not days, and buys nothing.** The Yard says so out loud. If it ever gains an effect, that sheet is the first thing to change.
- **A full-screen state must not borrow another screen's layout.** `Loading road…` rendered left-aligned for as long as it existed because it reused `.cr-screen--briefing`, whose children sit in a 560px column. Centred states get `.cr-screen--loading`.
- **Measure a screen before adding to it.** C44 and C45 each added a block to the briefing and C44 added five bars per card to the Yard; nobody measured, and the Yard reached 3.7 phone screens with Start the run below the fold on the briefing. The probe is three lines in a Playwright page: `scrollHeight` vs `clientHeight` on `.cr-screen` at 390x844. Anything past about 1.25x on a screen the player acts on wants restructuring, not smaller type.
- **A long card list on a phone goes sideways, not down.** `.cr-ride-grid` and `.cr-rides` are horizontal snap strips below 700px and the original grid above it. Cards in a strip line up, so the same row sits at the same height on every card — which is the comparison a stacked list cannot give.
- **About and Account are long on purpose.** Their bulk is the disclosure, the privacy notice and the consent copy (guardrails 3 and 10). Do not trim them to win a screen of scroll; trim a layout instead.
- **The brake is a level, not a one-shot, and the gas is nobody's.** C46 reads a flick down as "hold the brake while the thumb is on the glass" and holds the throttle itself (`controls.autoGas`). `step()` lets Gas win over Brake, so anything that synthesises input has to drop the gas bit to brake at all. The input bits are unchanged, so the ghost log, the balance bots and `isPlausibleRun` are all untouched by this.
- **One-shot input bits need a blank tick behind them.** The sim is edge-triggered on `prevInput`, so two of the same bit on consecutive ticks is one press. `InputController` queues one-shots and inserts the gap; anything that feeds bits in by hand (a bot, a test, a replay) has to do the same or lose every second input.
- **Gesture thresholds live in `packages/content/data/controls.json`** and the state machine that reads them is pure (`apps/game/src/input/gestures.ts`) — no DOM, so it is testable in the node environment. Keep new gesture logic there rather than in the pointer handlers, or it stops being testable the moment it matters.
- **`bonuses.onBeatTaps` is 2 because a double tap is two taps.** Raise it and the beat pad's copy, the briefing and the tutorial all start promising a gesture that no longer earns the bonus. The content test ties the on-beat window to it; the HUD copy reads `×1.5` off `onBeatPermille` rather than spelling it out.
- **The API is `api/` at the repo root, not `apps/api`.** It is its own workspace package (`@cr/api`), listed ahead of `apps/*` in `pnpm-workspace.yaml`; `apps/` is the frontend only. Moving a package inside a pnpm workspace breaks the relative symlinks in its `node_modules` — delete that folder and re-install, or every dependency resolves as `any`.
- **Abuse limits live in `packages/content/data/limits.json`**, with `CR_*` env overrides resolved once in `api/src/limits.ts`. The client reads the same file to tell the player how long a lockout or a link lasts — do not re-inline either number.
- **`isPlausibleRun` is in `@cr/sim` and runs on both sides.** Any new Crowd multiplier in `step.ts` has to be added to `maxCrowdFor()` in the same change, or the server starts rejecting legitimate runs with a 422. That is exactly what C28 and C30 did to it.
- **A name-only account's only credential is the device key in `localStorage`** (`apps/game/src/deviceKey.ts`). There is no password and no address, so clearing site data destroys the account and no other device can ever reach it — which is why `emailPrompt.ts` exists. Never make a name alone sufficient to resume an account from a new device: anyone can type a name.
- **A posted score is measured against `maxCrowdFor(delivered)`, not against the schema's range.** A test that posts a big Crowd with `delivered: 0` gets a 422 and looks like an auth bug. Scale the claim to what the run delivered, as the C41 plausibility tests do.
- **A permille threshold compared against the value it is a permille of can be unsatisfiable.** `momentum.fastThresholdPermille` was 1050 of a speed `step()` clamps to 1000 of, so the momentum multiplier sat at its floor for every run ever played (found in C44). When a config number gates a mechanic, probe that the mechanic fires before trusting it — a dead multiplier is silent.
- **A ride is `handling` in `rides.json`, permille of the matching `simConfig` number** (C44), and the sim takes it through `rideSimTraits(ride)`. Use that bundle: the live run, the ghost re-simulation and the balance bot all have to agree about how a ride drives, and spelled out by hand they had already drifted — the balance bot was testing a neutral version of all seven rides. A new ride field needs adding to the bundle or it never reaches the sim.
- **Flavour text that names a mechanic is a claim, and claims rot.** C26's size rule makes a flood transparent to S and M and blocks **L**, which is the opposite of what "a bus wades floods" suggests; C44's first draft shipped it backwards. The ride copy test in `packages/content/test/content.test.ts` ties the testable claims (floods, narrow gaps, ploughing, free hit, magnet) to the data.
- **A flex item's automatic minimum size only applies while `overflow` is `visible`.** So the `min-height: 0` the studio needs is a no-op on a screen that already sets `overflow: auto` (the briefing). Measure the scroller before writing the fix — `scrollHeight - clientHeight` on the element that scrolls, and scroll it before asking whether a button is reachable.
- Contender choice is in `cr-contender`, not `cr-storage`. Score/share paths must check consent.
- **Changing any string in `legal.json` means bumping `legal.version`.** Acceptance is matched against that exact version, so edited copy with an unchanged version means people are recorded as having accepted text they never saw. The bump makes everyone re-accept, which is the intended cost.
- **A control that was legible before C38 is not necessarily legible now.** `--cr-paper` on `--cr-surface` is cream on white: invisible. It shipped on `.cr-daily-chip` (C40) and on every control in the look editor (C43). When a panel becomes a white card, every descendant's colour has to be re-read.
- Screens live in `apps/game/src/ui/`, not `App.tsx`: the four menu screens (About, Settings, Account, Convoy Yard) share `ui/MenuChrome.tsx`, and C40 added `ui/RosterScreen.tsx` and `ui/SummaryScreen.tsx`. `.cr-sheet` is the card; `.cr-card` is the old pre-C38 cream one. What is left in `App.tsx` is Splash, Studio, Briefing, Paused and the run.
- **`.cr-screen` is `flex: 1` with no `min-height`, so a screen whose content is tall grows past `.cr-shell` and off the bottom of the phone.** A screen that must not grow (the studio) needs `min-height: 0` on itself *and* `minmax(0, 1fr)` on any grid track meant to shrink — plain `1fr` is `minmax(auto, 1fr)` and refuses.
- **`.cr-screen` is a fixed-height flex column.** A screen that can overflow needs `overflow-y: auto` *and* `flex: none` on its direct children, or the content is silently squeezed to the viewport instead of scrolling. This shipped three times (the C39 settings family, the C40 result page); check it on any new screen.
- **Driving the app from Playwright:** Vite's HMR serves the store as `/src/state.ts?t=<stamp>`, so `import('/src/state.ts')` in the page gets a *second* store instance whose `setState` changes nothing on screen. Find the URL the app actually loaded in `performance.getEntriesByType('resource')` and import that.
- The privacy floor is `campaignMap.standings.minPlayersPerRegion` in `map.json`. `CR_MIN_PLAYERS` only overrides it for a local demo — do not re-inline the number.
- Default ride is **trek**. Okada unlocks at 150 Following.
- Drop new state JSON under `packages/content/data/states/` — no loader edit.
- Community Rally Map is C14. Live board + local board are this device only.
- E2E: `pnpm test:e2e` (not part of `pnpm verify`).
- Animate CTAs with box-shadow, not transform (Playwright).
- **Visual rebuild (C20+):** environment glTF assets live under `apps/game/public/models/<biome>/`, loaded via `apps/game/src/render/assets.ts` (`loadAsset`/`preloadBiome`/`buildInstancedProp`). CC0 only (Kenney so far); characters/rides/gameplay props stay procedural (character.ts/props.ts) per ADR-0005/0007/0008 — never replace those with CC0 packs.
- `pnpm --filter @cr/game dev` → `/debug-assets.html` is a dev-only asset-pipeline sanity page (not built into `dist`). Useful for checking a new biome kit loads before wiring it into `world.ts`. Add `?face=1` for a close-up character/face view (light background, no world) — useful for any future `character.ts` work.
- Flat decal meshes mounted on curved geometry (e.g. the face plate on the cranium sphere) must clear the parent surface at every covered point, not just at the decal's own center, or the parent occludes the decal's middle. Custom vertex-shader patches that need a normal should use the raw `normal` attribute, not `objectNormal` (only declared under `USE_ENVMAP`/`USE_SKINNING`) — see `docs/chunks/C21.md`.
- `.claude/launch.json` (both at repo root and at the Claude Code primary-working-directory root) configures `preview_start` for the game dev server on port 5173.
- **Weather (C30):** the real clock is read exactly once, in `App.tsx` right next to the run's `seed`, via `computeWeather()` in `apps/game/src/weather.ts`. Never add a `Date`/`Math.random` call anywhere else for weather/time-of-day — pass the result through props instead, same as every other run-start decision.
- A long edit session can leave the running `pnpm dev` server's Vite HMR state stuck showing a stale error even after the on-disk files are fixed (seen once in C30, around a content-schema change) — if the console shows an error that a fresh `pnpm build` doesn't reproduce, restart the dev server (`preview_stop` + `preview_start`) before assuming it's real.
- **Node 22 required.** `pnpm verify`'s `content:lint` step uses `node --experimental-strip-types`; on Node 20 it fails with "bad option" before any content is checked. nvm has v22.23.1 — `export PATH="$HOME/.nvm/versions/node/v22.23.1/bin:$PATH"`. Worth an `.nvmrc`.
- **Portrait framing is measured, not hard-coded (C32).** `renderPortraits` derives its camera from `Box3.setFromObject(rig)`. Do not reintroduce literal eye heights — that is exactly what broke when C21 changed proportions. The `StudioScene` camera still uses a literal `0.92`; if proportions change again, check it too.
- **Headwear is newly exercised (C31/C32).** Before C31 every Contender had `headwear: none` and `prop: none`, so `headtie`/`hardhat`/`sailor`/`headphones` and the `fan`/`wrench`/`lantern`/`speaker` props had never actually rendered. `headtie` turned out to be broken. The remaining untested values in the schema are `cap`, and the outfit options players can pick in the studio.
- **Adding a state is still JSON-only (C34).** Drop a file in `packages/content/data/states/`; `import.meta.glob` finds it. But `hazards` is a closed enum now (`hazardSchema` in `schemas.ts`) — add the value there first. `farewellLine` is optional on purpose: leave it out rather than inventing a greeting in a language you cannot check.
- **Per-state copy must come from the pack, not the renderer (C34).** The border gate and the finish sign were string literals in `GameRenderer`, so every state greeted the player with "WELCOME TO LAGOS". They now come through `RenderOpts.gate`/`.finish` from `gateSign`/`finishSign` in `trail.ts`, which are pure and tested. Anything else that reads as "this state's" copy belongs in the pack too.
- **Only Lagos is unlocked at today's date.** To see another state in the browser, temporarily change the default in `campaignRows(now = Date.now())` in `trail.ts` — and change it back. `?debug` shows draws/tris; `?debug&debugZ=<metres>` jumps along the course (1370 lands at the finish gantry).
- **Port 5173 may belong to another project.** `.claude/launch.json` has a `game-alt` entry on 5174 for when it does; `preview_start` will move again (to 5175) if 5174 is taken too.
- **Hemisphere light is not put through the toon ramp (C33).** It is a flat floor under every surface, so raising it does not brighten a scene — it *flattens* it, by pushing everything onto the ramp's top step. Day/night intensities live in named constants at the top of `world.ts`; `addLights` in `studio.ts` serves the studio and the portrait bakes. If the art ever looks washed out, check the hemisphere value before anything else.
- **Shadow maps are on the character screens only (C33).** The gameplay world still uses `blobShadow`. `patchBend` displaces vertices in the vertex shader and that patch is *not* applied to three's depth material, so any world shadow map would misalign with the road curve until the bend is patched into a custom depth material.
- **Outline shells must stay out of the shadow pass.** They are BackSide copies of the same geometry; letting them cast thickens and offsets every shadow. `castShadows()` in `studio.ts` skips anything using `outlineMat()`.
- **`PCFSoftShadowMap` was removed in three 0.186** and silently falls back to `PCFShadowMap` with a console warning. Set the type explicitly.
- **One shared WebGL context for portrait bakes (C33).** `renderPortraits` used to create and destroy a renderer per call, and the picker calls it twice in the same tick — past the browser's live-context cap (commonly 16) the oldest is dropped and the bake silently produces nothing, which looks exactly like the C32 blank-cards bug. Do not go back to a per-call renderer.
- **Character radii are related, not independent (C33).** Chest-level clothing radii must stay under `ARM_X` or they swallow the arms; outer layers use `LAYER_Z` so they stay proud of the chest in depth too. `apps/game/test/silhouette.test.ts` guards the invariants.
- **The campaign map (C35)** builds its own Three.js materials in `render/mapBoard.ts` instead of using `render/materials.ts` — those are patched with the road's shared `bend` uniform, so the map would inherit the road curve the moment a run set it. Keep it that way.
- **Map region layout lives in `packages/content/data/map.json`,** not in the component. A new state needs a hex there as well as a pack; a test fails if the two lists disagree.
- **Never add a percentage to the board** (guardrail 2 — no polling-style percentages until 200 uniques per state). The tally bar counts regions held; the focus panel lists Crowd integers.
- **`rivalCrowds` must stay party-agnostic** (guardrail 5). Party identity may only decide which *rank* a party is handed, never the value — there is a test for this, and for the equal-regions-held invariant.
- **The API bundles `@cr/content`,** so anything added there has to survive plain Node. `state-packs.ts` guards `import.meta.glob` on `import.meta.env` and **not** on `typeof import.meta.glob` — Vite replaces the glob *call* at build time but leaves the function undefined at runtime, so the obvious guard silently empties the pack list in the browser while still passing under Vitest.
- **Run the API with a database:** `DATABASE_URL=postgres://… pnpm --filter @cr/api build && node api/dist/server.js`. `CR_MIN_PLAYERS` lowers the standings privacy floor for local testing; never lower it in production.
- **CORS lists both dev host spellings.** `localhost:5180` and `127.0.0.1:5180` are different origins, and only one being allowed looks exactly like the server being down.
- **The map's region outlines come from `@cr/content`'s `mapgeo.ts`,** keyed on lattice points so neighbours share edges. Never jitter a region's outline per region.
- **Hazards are no longer flavour (C45).** A state's `hazards` reweight its obstacle table and multiply the player's handling, composed by `roadProfile()` in `packages/content/src/road.ts`. Adding a hazard means adding it to `hazardSchema` **and** giving it an effect in `hazards.json` — a test fails if the two lists disagree, and another fails if the effect does nothing at all.
- **`go-slow` is in 37 of the 38 packs**, so it is the baseline of a Nigerian road, not a difficulty dial. Keep its numbers within 5% of neutral (there is a test) — anything harsh there is harsh on nearly every road in the game and distinguishes nothing.
- **Composed road numbers are clamped in `road.json`, and the clamps are load-bearing.** Three hazards multiply; the floor exists because a ride multiplied below `baseSpeedUm` sits pinned at the coast speed with the gas pedal doing nothing. If you add a harsh hazard, re-run the content test that sweeps all 38 packs × 7 rides.
- **Anything that counts how many entities fit on a course must use `course.roadGapFloorPermille`.** A busy road packs spawns tighter than `spawn.gapMinMm`; `maxCrowdFor` in `plausibility.ts` is the one place that cares, and a content test ties the road clamp to that floor.
- **Road advice copy is derived, never written per state.** `rideRoadFit()` reads the composed profile, so the briefing cannot promise what the course generator will not do. A ride sitting exactly on the baseline (the keke, on every stat) says nothing — do not add a rule that praises the yardstick.
